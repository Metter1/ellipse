## Как понято определение апекса

В этой задаче апекс трактуется как **правая крайняя точка эллипса**, то есть точка эллипса с максимальной координатой `x`. Именно поэтому апекс определяется не как конец большой полуоси, а как результат максимизации `x(t)` у параметрического уравнения повернутого эллипса.

Для эллипса с центром `(cx, cy)`, полуосями `a`, `b` и углом `theta` используется параметризация:

```text
x = cx + a cos t cosθ - b sin t sinθ
y = cy + a cos t sinθ + b sin t cosθ
```

Правая крайняя точка находится из условия максимума `x(t)`. В коде это выражено через:

```ts
const t = Math.atan2(-b * sin(theta), a * cos(theta));
```

После этого координаты апекса вычисляются подстановкой найденного `t` обратно в параметризацию.

## Почему апекс не совпадает с концом большой полуоси

Конец большой полуоси — это точка, полученная движением из центра на расстояние `a` вдоль направления `theta`:

```text
(cx + a·cosθ, cy + a·sinθ)
```

Эта точка лежит на большой оси эллипса, но не обязана быть самой правой точкой фигуры. После поворота эллипса координата `x` зависит сразу от двух слагаемых: вклада большой полуоси и вклада малой полуоси. Поэтому максимум по `x` обычно достигается в другой точке эллипса, а не в конце большой полуоси

## Алгоритм пересчёта при перетаскивании центра

При перетаскивании центра реализовано поведение строго по условию:

- `cy` принудительно фиксируется на оси керна `y = 110`;
- `cx` двигается только в пределах видимой области по горизонтали;
- `a`, `b`, `theta` не меняются;
- апекс и габаритный прямоугольник пересчитываются автоматически как производные от новых параметров.

Дополнительно введена защита от выхода эллипса за вертикальные границы керна. Если после смещения центра текущий вертикальный полуразмер эллипса уже не помещается между `coreTop` и `coreBottom`, полуоси пропорционально уменьшаются до допустимого размера. Это гарантирует, что эллипс остаётся геометрически корректным и не выходит за рабочую область.

## Алгоритм пересчёта при перетаскивании апекса

При перетаскивании апекса центр эллипса остаётся фиксированным, а точка, в которую пользователь перетащил ручку, должна стать новой правой крайней точкой эллипса.

Используется следующий подход:

1. Новая позиция апекса сначала ограничивается допустимой областью: по `x` нельзя уйти левее центра, по `y` нельзя выйти за вертикальные границы керна.
2. Вводятся обозначения:
   - `u = apexX - cx`;
   - `v = apexY - cy`;
   - `d = availableHalfHeight` — максимально допустимый вертикальный полуразмер внутри керна.
3. Далее используется система соотношений для повернутого эллипса:

```text
u²   = a² cos²θ + b² sin²θ
v·u  = (a² - b²) sinθ cosθ
d²   = a² sin²θ + b² cos²θ
```

4. Для фиксированного `theta` из первых и третьих уравнений выражаются `A = a²` и `B = b²`.
5. Затем подбирается такой `theta`, при котором выполняется второе уравнение. В текущей реализации это делается численно: сначала грубым проходом по диапазону углов, затем локальным уточнением на лучшем интервале.
6. После нахождения угла вычисляются `a` и `b`, применяются минимальные ограничения, а также нормализация `a >= b`.

Практически это означает следующее: dragged-точка интерпретируется как новый правый апекс, центр остаётся на месте, а эллипс подстраивается так, чтобы одновременно:

- сохранить корректную геометрию;
- иметь нужную правую крайнюю точку;
- не выйти за вертикальные границы керна.

## Ограничения и граничные случаи

В решении обработаны следующие ограничения:

### Область керна

Используется фиксированная рабочая область:

```ts
{
  width: 800,
  height: 220,
  coreTop: 30,
  coreBottom: 190,
  coreAxisY: 110,
}
```

Центр всегда живёт на оси `coreAxisY`, а все вычисления выполняются относительно этой области.

### Ограничения для центра

- центр нельзя увести левее `x = 0` и правее `x = 800`;
- `cy` всегда остаётся равным `110`;
- если при новом положении центра эллипс не помещается по высоте, полуоси уменьшаются до допустимых значений.

### Ограничения для апекса

- апекс нельзя увести левее центра, поэтому `x` ограничивается снизу значением `cx + 1`;
- апекс нельзя увести выше `coreTop` и ниже `coreBottom`;
- если вертикальное смещение апекса запрашивает недостижимую конфигурацию, оно ограничивается максимально достижимым режимом внутри керна.

### Геометрическая корректность

Чтобы эллипс не вырождался и не становился некорректным, дополнительно введены ограничения:

- `a >= MIN_A`;
- `b >= MIN_B`;
- если после вычислений получается `b >= a`, значения нормализуются так, чтобы большая полуось оставалась большей;
- при почти горизонтальном положении апекса используется отдельная ветка расчёта для устойчивого случая `theta ≈ 0`;
- при численной нестабильности около `cos(2θ) = 0` такие значения угла исключаются из допустимых.
